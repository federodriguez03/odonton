# Base de demostración 2026

La base autorizada es exclusivamente `odonton_demo_2026`. El generador usa semilla fija `20261208`, fecha de corte explícita `2026-11-13` y zona horaria `America/Buenos_Aires`.

## Preparación

Definir localmente las cinco contraseñas `DEMO_*_PASSWORD` indicadas en `backend/demo-2026.env.example`. No se imprimen ni se guardan sus valores. Luego ejecutar desde la raíz:

```powershell
powershell -ExecutionPolicy Bypass -File backend/scripts/prepare-demo-2026.ps1
```

El preparador verifica servidor y nombre, crea la base si falta, importa únicamente el esquema vigente desde `odonton_ficha_20261109_test` y ejecuta la carga. Si encuentra tablas sin el marcador del generador, se detiene. Una reejecución valida firmas y no duplica registros.

Si la base fue generada con claves efímeras de validación, establecer las definitivas cargando las mismas variables y ejecutando, con `DB_NAME=odonton_demo_2026`:

```powershell
node backend/scripts/set-demo-2026-passwords.js
```

El cargador sólo actualiza las cinco cuentas marcadas como demo, invalida sesiones previas y mantiene el cambio obligatorio. No imprime contraseñas.

El catálogo copiado se limita a prestaciones y referencias necesarias. Los aranceles conservan fuente, versión y condición documental; las duraciones y precios propios usados para agenda están marcados en `prestaciones_historial` como estimaciones y valores ficticios de demostración.

## Seguridad y conexión posterior

`backend/scripts/start-demo-local.ps1` inicia el backend con `DB_NAME=odonton_demo_2026`, archivos bajo `backend/uploads/demo-2026` y modo de diagnóstico. No inicia automáticamente WhatsApp, bot, scheduler ni recordatorios. Sólo el dueño puede consultar estado/QR e iniciar, reintentar o desconectar el cliente; el procesamiento de mensajes y todos los envíos se rechazan. Para recuperar el bloqueo demo completo, iniciar sin `WHATSAPP_DIAGNOSTIC_MODE=true`.

La configuración anterior de `backend/.env` no se modifica. Para volver, detener el proceso demo e iniciar:

```powershell
powershell -ExecutionPolicy Bypass -File backend/scripts/start-previous-local.ps1
```

Para comprobar base efectiva, bloqueo de envíos y accesos, ejecutar con las variables locales cargadas:

```powershell
node backend/scripts/verify-demo-local.js
```

No reutilizar la carpeta de sesión de WhatsApp.

Las cuentas quedan activas, identificadas como demo y con cambio obligatorio de contraseña temporal. Los perfiles profesionales son ficticios, confirmados y usan IDs independientes de los usuarios.

## Cobertura y límites

Incluye pacientes, agenda anual, atenciones con snapshots, odontogramas actuales, prótesis estructuradas, declaraciones versionadas, cargos/pagos/anulaciones, archivos sintéticos y solicitudes WhatsApp sin transporte. No se generan consentimientos, firmas, mensajes ni recordatorios. Las duraciones demo no se atribuyen a la fuente arancelaria.

Resultado generado el 13 de noviembre de 2026:

- 120 pacientes, 5 usuarios y 3 perfiles profesionales ficticios.
- 12 prestaciones documentadas, de las cuales 8 tienen precio propio fijo ficticio, 2 están a convenir y 2 sin definir.
- 700 turnos: enero 52, febrero 55, marzo 58, abril 60, mayo 62, junio 64, julio 61, agosto 59, septiembre 60, octubre 62, noviembre 65 y diciembre 42.
- Estados: 330 realizados, 110 cancelados, 109 ausentes, 150 programados y 1 con reprogramación solicitada pendiente.
- 117 turnos con múltiples prestaciones y 247 atenciones con odontograma histórico.
- 65 versiones de declaraciones: 45 completas, 20 incompletas y 10 pacientes con más de una versión.
- 220 cargos y 187 pagos: 59 cargos impagos, 53 parciales, 108 saldados y 4 pagos anulados con trazabilidad.
- 24 asociaciones de archivos sintéticos, 18 prótesis estructuradas y 4 solicitudes WhatsApp ficticias sin transporte.

Las validaciones confirmaron ausencia de solapamientos, huérfanos, pagos excesivos, actividad clínica o financiera futura y solicitudes pendientes duplicadas. `odonton_db` y `odonton_ficha_20261109_test` conservaron sus cantidades previas.

El resumen también queda guardado en `demo_generator_runs.summary`. Los fixtures son sintéticos y reutilizables; no contienen información personal real.
